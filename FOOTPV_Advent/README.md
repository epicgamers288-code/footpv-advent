# FOOTPV · До Нового гола!
Telegram Mini App футбольной академии. Сезон с 11 по 30 декабря 2026 года по Минску, финальный розыгрыш 31 декабря. Этот пакет предназначен для локальной репетиции и последующей интеграции организатором.

## Быстрый старт на компьютере
Установите Docker Desktop с Compose v2 либо Docker Engine с Compose. Распакуйте **весь** ZIP и откройте терминал в папке с этим README. Для первого запуска нужны интернет и загрузка образов.
```sh
docker compose -f compose.test.yml up --build -d
```
Откройте http://localhost:8091. Вход с тестовым номером **1** даёт доступ к разделу **Профиль → Панель организатора**. Укажите **10 декабря 2026, 10:00** и внесите пробные призы по порядку. Затем выберите **11 декабря 2026, 09:00**. В календаре откроются первая коробка, первое колесо и игра. Номера от 2 до 99999 создают обычных тестовых участников. Для второго игрока используйте приватное окно.

Репетиционные часы продолжают идти после выбранного момента. Переходите вперёд, чтобы увидеть закрытие игр и начисления. Возврат часов назад не отменяет уже выданные билеты и закрытые рейтинги. Для нового чистого прогона используйте новый Compose project с параметром `-p другое_имя`. Команда `docker compose -f compose.test.yml down` останавливает сервисы и сохраняет том базы.

## Состав
- `web/` содержит React, TypeScript, Vite, Phaser, интерфейс игрока и организатора. Графика в `public/`, индивидуальные отрисовщики полей в `src/games/`. Десятая игра использует четыре предыдущих механики. Сцены приходят от сервера по одной. В ZIP есть также собранный клиент `web/dist/`.
- `server/` содержит API Axum/Tokio, проверку Telegram, SQLx-миграцию PostgreSQL, подсчёт очков и обработчик закрытия периодов. SQL-ограничения и транзакции защищают слоты попыток и начисления.
- `deployment/bot_module.py` добавляет команды в существующий диспетчер бота. Исходники трёх вариантов знака FOOTPV сохранены в PNG. Четыре подарочные коробки отрендерены в Blender, исходная сцена воспроизводится скриптом `art/gifts.py`. Короткие звуки синтезируются Web Audio.
- `tests/` содержит сценарии репетиции, браузерных проверок и независимой проверки розыгрыша. Фактические результаты и границы проверки приведены в `TEST_REPORT.md`.

## Правила сезона
Дверь и колесо доступны с 09:00 до полуночи. Игра открывается в первый день пары в 09:00 и продолжается весь второй день, включая время до 09:00. Чтобы начать новую попытку, до закрытия должно хватать времени на её полную длительность. Попытка списывается при серверном старте. После перезагрузки используйте «Продолжить попытку». Время вне приложения входит в лимит. Для места в рейтинге нужна завершённая попытка как минимум с одним действием. Полное равенство очков и точных действий даёт одинаковое место с пропуском последующего номера. Правила наград и вероятность колеса доступны из колеса и профиля.

Для следующего года используйте отдельную базу, новый секрет сезона создаётся автоматически. Месяц и дни заданы условиями мероприятия. Приложение прекращает запуск при попытке использовать базу другого года.

## Подготовка рабочего контура
1. Назначьте ответственного за призы и рассмотрение результатов. До публичного запуска организатор проверяет правила бесплатного мероприятия, порядок участия родителей, сроки хранения данных и обращения участников применительно к Беларуси. Текст экранов доступен в `web/src/Profile.tsx`.
2. На сервере с Docker настройте домен, DNS и входящие TCP 80/443. Скопируйте `.env.example` в `.env`. Заполните `PUBLIC_HOST` доменом без протокола, `BOT_TOKEN` действующим токеном, `ADMIN_IDS` числовыми Telegram ID через запятую и `POSTGRES_PASSWORD` длинным случайным URL-безопасным паролем. Рабочие токены и файл `.env` держите вне репозитория.
3. После разрешения организатора команда `docker compose up --build -d` поднимает Caddy, API и PostgreSQL. Caddy получает TLS для указанного домена. Внешне доступны только HTTP/HTTPS. Проверка сервиса – `GET /api/health`. Скопируйте и сохраните опубликованное обязательство из `GET /api/public-proof` до старта мероприятия.
4. В существующем боте подключите адаптер ниже и проверьте новые команды в личном чате. После интеграции пройдите одну тренировочную сессию в Telegram Android, iOS и Desktop на отдельной тестовой установке. При проверке живой Telegram-подписи используйте обычную серверную сборку, отдельного тестового бота, отдельный домен и отдельную базу без суффикса `_test`. Компиляционная опция `rehearsal` предназначена только для локальных тестовых пользователей.
5. Включите резервное копирование PostgreSQL с момента создания сезона. В резервной копии хранятся seed и связь билетов с владельцами. Доступ к резервным копиям и базе должен быть у оператора сервера. Восстановление после сбоя должно продолжать тот же сезон с тем же обязательством.

### Интеграция бота
Вставьте обработку события **в уже действующий диспетчер**. Действующие команды академии сохраняют свои обработчики. Если /help или /rules заняты, добавьте кнопку адвента в существующий ответ. Обычный /start остаётся прежним. Deep link `https://t.me/FOOTPV_bot?start=advent` открывает ветку мероприятия.
```python
from deployment.bot_module import advent_reply

# В ветке адвента действующего обработчика Telegram Update:
reply = advent_reply(update, public_url)
if reply is not None:
    await bot.send_message(**reply)  # для библиотек, принимающих Bot API kwargs
    return
# Продолжить существующую маршрутизацию.
```
Адаптер возвращает словарь формата Bot API, который можно передать HTTP-методу sendMessage. Конкретная библиотека бота может требовать преобразовать reply_markup в собственный тип. Адаптер не регистрирует webhook, не включает polling и не меняет меню @FOOTPV_bot. Рассылки выполняет сервер только для подписавшихся участников. После неопределённого ответа Telegram запись остаётся в sending/uncertain для ручной сверки оператором. Это исключает автоматический повтор сообщения, которое Telegram мог уже доставить.

## Финальный протокол
До 11 декабря внесите список призов в требуемом порядке. 31 декабря нажмите «Зафиксировать билеты». Сервер завершит начисления и сохранит отсортированный список пар [номер билета, случайный публичный псевдоним владельца] и его SHA-256. Сохраните протокол до выбора победителей. Затем отдельной командой «Провести розыгрыш» сервер записывает результат и раскрывает seed. Повторный запрос возвращает тот же результат. При нехватке участников оставшиеся призы ждут отдельного решения организатора.

Откройте карточку розыгрыша и скачайте draw.json. Для независимой проверки сопоставьте заранее сохранённые commitment и digest с итоговым файлом и выполните:
```sh
python tests/verify_draw.py draw.json
```
Проверка воспроизводит SHA-256(seed:digest:counter), берёт первые 64 бита в big-endian, использует отбрасывание хвоста диапазона перед остатком от деления и исключает остальные билеты выигравшего владельца. Публичный endpoint скрывает seed до фиксации победителей.

## Повторение проверок
В `web/` выполните `npm ci` и `npm run build`. В `server/` выполните `cargo test --locked` и `cargo build --locked`. Использованы Node 24 и Rust 1.100. Для сквозного теста запустите новый чистый репетиционный контур. Укажите переменную `API_URL=http://localhost:8091/api` и выполните `python tests/season.py`. Для `tests/browser.py` понадобятся Python Playwright, Chromium, `WEB_URL=http://localhost:8091` и путь к Chromium в `CHROMIUM`. Каждый сценарий запускайте на отдельной чистой базе. `tests/restart.py` рассчитан на прямой запуск тестового API из корня проекта с DATABASE_URL, ADMIN_IDS и TEST_SERVER_PID. SQL-проверку запускайте через psql в репетиционной базе.
